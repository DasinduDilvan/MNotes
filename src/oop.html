Common Exam Traps

⚠️ Watch For These
  • Writing a = a; inside a setter — assigns parameter to itself. Fix: this.a = a;
  • Java does not support multiple inheritance of classes — class C extends A, B won't compile.
  • Pairing an instance method with a static method of the same signature in a related class = compile error.
  • Down-casting needs an explicit cast: Car c = (Car) obj;
  • Implementing only some abstract methods without marking the subclass abstract won't compile.
  • Overloading can never be achieved by changing return type alone.
  • A super() call, if explicit, must be the very first statement in a constructor.
  • Once constructed, a constructor can't be called again — new is the only trigger.

01

Introduction to OOP

What is OOP?

Object-Oriented Programming is a paradigm that wraps data and the behavior related to that data into bundles called objects. Objects are built from blueprints defined by a programmer, called classes.

A program written the OOP way is a collection of objects: each object decides for itself what to do with a message it receives. The focus is on data, not on the exact procedure used to manipulate it.

Why Object Orientation?

  • Modularity — an object's source can be written and maintained independently.
  • Information-hiding — interacting only through methods keeps internals hidden.
  • Code re-use — an object already built and tested can simply be used.
  • Pluggability & debugging ease — a problematic object can be swapped for a replacement.

Procedural vs. Object-Oriented

Procedural: data and behavior stay separate — free-floating functions operate on a plain data structure.

OO: nouns become classes, verbs become methods. Data and operations are grouped together.

Java — OO Approach
public class Account {
    private int accountNum;
    private double balance;
    private char accountType;

    Account(int accountNum, char accountType) {
        this.accountNum = accountNum;
        this.accountType = accountType;
    }

    public void deposit(double amount) {
        balance += amount;
    }

    public boolean withdraw(double amount) {
        if (amount > balance) return false;
        balance -= amount;
        return true;
    }

    public boolean transfer(Account to, double amount) {
        if (!withdraw(amount)) return false;
        to.deposit(amount);
        return true;
    }
}

Class, Object, Instance, Instantiation

📌 Class vs. Object
Class: visible in source code; the code is never duplicated.
Object: has its own copy of data; is active in a running program; occupies memory.

Every object has three characteristics:

  • State — its properties and current values.
  • Behavior — what it can do through its methods.
  • Identity — what tells two objects of the same class apart.

Alan Kay's Rules

💡 Alan Kay's Five Rules
  1. Everything is an object.
  2. A program is a bunch of objects telling each other what to do, by sending messages.
  3. Each object has its own memory, made up of other objects.
  4. Every object has a type.
  5. All objects of a particular type can receive the same messages.

Classes & Objects

Declaring a Class

Java — Extended Form
package com.example;
import java.util.*;

public class ClassName extends BaseClass implements Interface1, Interface2 {
    // Fields
    // Initializers
    // Constructors
    // Methods
    // Inner classes / interfaces
}
📌 Rules
  • Class names start with a capital letter and are usually nouns.
  • A public class must live in a file with the same name, ending .java.
  • A single file can't contain two or more public classes.

Fields & Methods

A field is a variable declared in the class body, outside any method. A method is a named collection of statements that runs only when called.

Access Modifiers

  • public — callable from any class.
  • private — callable only from inside the same class.
  • protected — callable from the same package or from subclasses.
  • default (package-private) — callable only from the same package.

Constructors

  • Name must exactly match the class name.
  • No return type, not even void.
  • Called automatically via new.
  • If no constructor is defined, Java supplies a default no-arg one.
Java — Parameterized Constructor
public class Employee {
    private String Name;
    private int Age;
    private char Gender;

    Employee(String n, int a, char g) {
        Name = n;
        Age = a;
        Gender = g;
    }
}

The this Keyword

🐛 Common Bug
a = a; assigns the parameter to itself. Use this.a = a; to reach the field.

Constructor Chaining

Java
public class Box {
    double width, height, depth;

    Box() {
        this(1.0, 1.0, 1.0);
        System.out.println("Default box created");
    }

    Box(double side) {
        this(side, side, side);
    }

    Box(double w, double h, double d) {
        this.width = w;
        this.height = h;
        this.depth = d;
    }
}

Initializer Blocks

Java
public class InitializerTest {
    {
        System.out.println("Initializer block executed");
    }

    InitializerTest() {
        System.out.println("Constructor executed");
    }
}

Statics

A static field or method belongs to the class itself, not to any one instance.

Java — Static Counter
public class Counter {
    private static int instanceCount = 0;

    Counter() {
        instanceCount++;
    }

    public static int getInstanceCount() {
        return instanceCount;
    }
}

Preventing Instantiation

Java — Utility Class
public class MyMathUtils {
    private MyMathUtils() {}  // prevents instantiation

    public static double square(double x) {
        return x * x;
    }
}
03

Inheritance

What is Inheritance?

A subclass acquires all properties and behaviors of a superclass — an is-a relationship, built with extends. Java supports only single inheritance for classes.

Java
public class Vehicle {
    double speed = 40.0;

    public void start() {
        System.out.println("Starting…");
    }
}

public class Car extends Vehicle {
    public void drive() {
        System.out.println("Driving…");
    }
}

Types of Inheritance

  • Single — B extends A
  • Multilevel — A → B → C (chain)
  • Hierarchical — B, C, D all extend A
  • Hybrid — combination of the above
  • Multiple — NOT allowed in Java (Diamond Problem)
⚠️ The Diamond Problem
If CDBurner and DVDBurner both extend DigitalRecorder and both override burn(), a ComboDrive inheriting from both wouldn't know which version to use. Java sidesteps this by disallowing multiple class inheritance. Interfaces fill the gap.

Overriding vs. Hiding

Superclass Instance MethodSuperclass Static Method
Subclass Instance Method✅ Overrides❌ Compile error
Subclass Static Method❌ Compile error✅ Hides

Constructors in Subclasses

📌 Rules for super()
  • If used, must be the very first statement in the constructor.
  • If not called explicitly, the compiler inserts a call to the superclass's default constructor.
  • This chains all the way up to Object.

The final Keyword

  • final variable — a constant; value set once, never changed.
  • final method — cannot be overridden by any subclass.
  • final class — cannot be extended; all methods implicitly final.

Casting & instanceof

Java
// Up-casting (implicit)
Vehicle v = new Car();

// Down-casting (explicit)
Car c = (Car) v;

// instanceof check
if (v instanceof Car) {
    Car car = (Car) v;
    car.drive();
}

Polymorphism

What is Polymorphism?

The capability of an action or method to do different things depending on the object it acts upon.

  • Compile-time (static) → Method Overloading
  • Run-time (dynamic) → Method Overriding

Method Overloading

Java
class Calculation {
    void sum(int a, int b) {
        System.out.println(a + b);
    }
    void sum(int a, int b, int c) {
        System.out.println(a + b + c);
    }
    void sum(double a, double b) {
        System.out.println(a + b);
    }
}
⚠️ Warning
Overloading can never be achieved by changing the return type alone — the parameter list must differ.

Method Overriding & Dynamic Binding

Java
class Vehicle {
    public void start() { System.out.println("Vehicle starting"); }
}

class Car extends Vehicle {
    @Override
    public void start() { System.out.println("Car is starting"); }
}

// Dynamic binding in action:
Vehicle v = new Car();
v.start();  // "Car is starting" — actual object decides

Static Binding (Fields)

⚠️ Key Difference
Fields use static binding — resolved by the reference's declared type, not the object's actual type. Methods (overridable) use dynamic binding — resolved by the object's actual class.

Abstraction

What is Abstraction?

Hides implementation and exposes only what's essential. Achieved via:

  • Abstract class — 0% to 100% abstraction (can mix implemented and unimplemented methods).
  • Interface — 100% abstraction.

Abstract Classes

Java
public abstract class Bike {
    Bike() {
        System.out.println("bike is created");
    }

    abstract void run();  // no body

    void changeGear() {  // concrete method
        System.out.println("gear changed");
    }
}

public class Honda extends Bike {
    @Override
    void run() {
        System.out.println("running safely");
    }
}

Interfaces

Java
interface Drivable {
    int MAX_SPEED = 200;  // public static final
    void drive();           // public abstract
}

class Car implements Drivable {
    @Override
    public void drive() {
        System.out.println("Car driving, max " + MAX_SPEED);
    }
}

Encapsulation

What is Encapsulation?

Wraps code (methods) and data (fields) together into a single unit. Fields are made private and exposed only through public methods (getters/setters). Also called data hiding.

Java — Encapsulated Class
public class SalesPerson {
    private String name;
    private int id;
    private float commissionRate;
    private double sales;

    SalesPerson(String name, int id, double rate) {
        setName(name);
        this.id = id;
        setCommissionRate(rate);
    }

    public void setCommissionRate(double newRate) {
        if (newRate >= 0.0 && newRate <= 0.20) {
            commissionRate = (float) newRate;
        } else {
            System.out.println("Rate must be between 0 and 20%");
        }
    }

    public double computeCommission() {
        double commission = 0.0;
        if (sales > 0.0) commission = sales * commissionRate;
        sales = 0.0;
        return commission;
    }
}

Advantages

  • Providing only a getter makes a field effectively read-only.
  • Gives a class full control over its own data (validation).
  • Callers never need to know internal storage — representation can change later.
